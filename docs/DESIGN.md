# 设计思路：把展示与存放分开

这个项目最先要解决的不是“图标应该画成什么风格”，而是桌面整齐和原路径稳定之间的冲突。用户希望保留已经形成的操作记忆：去桌面保存、按旧图标辨认、从熟悉的位置找入口，自动化继续引用同一个位置。

## 1. 先理解“左、中、右”

左边栏、中间栏、右边栏来自用户原来摆放图标的物理区域。它们不是“工具、资料、业务”的代称。擅自按功能重新分类，即使分类看起来合理，也会破坏用户已有的空间记忆。

公开原型用桌面宽度三等分提供初始分区，并保留行优先顺序；对于不规则分组或多屏布局，允许在首次初始化时提供本地布局文件。算法只是初始建议，用户的安排是依据。

## 2. 美观不必从重画所有图标开始

原图标承载了用户的识别习惯，包括应用标记、文件类型以及文件夹预览。重新换一套统一图标可能降低查找效率。

因此保留 Windows Shell 给出的原图像，只设计收纳程序自身的入口。统一的是留白、字号、图标尺寸、对齐、焦点和动效节奏。长文件名在格子里省略，但原名、源路径和提示保留。

## 3. 收纳入口引用原件

原文件留在桌面原路径。收纳目录生成快捷方式，运行时同时保存原来源，点击后执行原入口。业务原件不会因为界面“归类”而搬动。

空间层与存储层由此可以分别变化：视觉上只剩一个入口，原文件仍能被既有程序按完整路径访问。Hidden 位会影响只枚举可见文件的程序，这一点不能包装成“所有自动化绝对零影响”。

## 4. 隐藏需要可恢复

先记录原状态、建立可用入口并持久化，之后才隐藏。只修改顶层项目的 Hidden 位；不递归、不删除原件、不修改 ACL。系统入口的显示与文件属性分开处理，已有注册表键只改指定值。

恢复不是反向“搬回文件”，而是恢复显示状态。恢复时先暂停自动收纳，避免两个功能互相抵消。程序退出、记录损坏和权限不足时，优先保留原件与可见性，不继续隐藏新项目。

## 5. 动效帮助理解进入与返回

入口可选择扇形或网格展开，三栏仍是实际的导航目录。点击分类进入下一层，Esc 返回，外部点击收回；快速关闭和重开能中断上一段动画。

展开主要用位移、缩放和透明度表达来源，不旋转原图标。尊重系统减少动画偏好，支持键盘焦点。子页随内容增长，受屏幕工作区限制，必要时滚动。

## 6. 新文件沿用已有模型

新保存的桌面项目只增加入口。保存稳定、没有写入占用且恢复记录写入成功后，再隐藏原图标；默认追加左边栏末尾。改变默认栏只影响以后新增项目。

Windows 文件标识用于匹配改名。原件被用户删除或移出桌面时，只移除本工具的导航。临时、下载中、系统和未跟踪的原隐藏文件跳过。自动收纳及登录启动均由用户主动启用。

## 当前取舍

- 原生 WPF / .NET Framework，沿用 Windows Shell，不引入浏览器界面或联网服务。
- 公开版移除个人桌面清单、业务命名、缓存、录屏、账号与路径。
- 当前以 Windows 10 单屏桌面验证为主；多屏、混合 DPI 和 Windows 11 需要社区验证。
- 当前不是文件备份、文件管理器替代品或跨设备同步工具。

产品构思与方向由项目发起者提出，代码实现使用 AI 辅助。本文记录最终被确认的设计，不把早期误解或代理偏好当作用户要求。
